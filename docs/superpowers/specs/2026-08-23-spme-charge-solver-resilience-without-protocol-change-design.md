# SPMe标准充电求解稳定性修复设计

日期：2026-08-23  
状态：已确认设计  
适用范围：`src/pybamm_w10` 的标准老化循环充电执行路径

## 1. 背景

现有350圈虚拟W10运行在完成9个老化循环后，于第10圈标准充电的
`4v_cv`阶段终止。底层错误为：

```text
IDA_ERR_FAIL: Error test failures occurred too many times during one step
or minimum step size was reached
```

失败发生在14.55 A恒流充电至4.0 V后，切换到4.0 V恒压充电至
0.05 A的阶段。当前后端为每个协议子阶段分别创建新的
`pybamm.Simulation`，并使用上一阶段的`starting_solution`重新映射状态、
计算DAE一致初值。第9圈相同切换附近已经出现约`1e-8`至`1e-7 s`的
内部时间步，说明该位置接近当前数值配置的稳定边界。

本设计只修复数值执行和失败恢复，不改变实验充放电流程，不调整电池
或退化参数。

## 2. 目标

1. 消除标准充电CC到CV控制切换处由重复Simulation构建和状态重映射
   放大的数值不稳定。
2. 对明确可恢复的SUNDIALS/IDA数值错误提供一次确定性重试。
3. 保证失败尝试不污染主状态、正式CSV或已提交检查点。
4. 保留逐阶段进度、轨迹、终止原因和墙钟耗时。
5. 改善失败取证，使失败能够定位到循环、阶段、步骤、求解尝试和最近
   有效检查点。
6. 通过从cycle 0开始的新运行验证数值修复，不把新旧数值执行算法混入
   同一正式结果集。

## 3. 非目标

本设计明确不包含：

- SEI、镀锂、LAM或容量参数校准；
- 电流、电压、截止条件、静置时间或阶段顺序调整；
- 在CC与CV之间插入静置、电流斜坡或额外稳定阶段；
- 放宽`rtol`或`atol`；
- 修改Step 5容量窗口算法；
- 修改Step 6 UDDS波形、事件保护或积分方法；
- 修改RPT节点或RPT流程；
- 允许无限重试或跳过失败阶段；
- 使用失败过程中的部分解继续正式运行。

## 4. 不可变实验协议

标准循环必须继续严格执行：

| 顺序 | 阶段 | 控制 | 终止条件 |
|---:|---|---|---|
| 1 | `3c_cc` | -14.55 A恒流充电 | 端电压达到4.0 V |
| 2 | `4v_cv` | 4.0 V恒压充电 | 充电电流绝对值降至0.05 A |
| 3 | `c4_cc` | -1.2125 A恒流充电 | 端电压达到4.2 V |
| 4 | `4p2v_cv` | 4.2 V恒压充电 | 充电电流绝对值降至0.05 A |
| 5 | `post_charge_rest` | 零电流静置 | 1800 s |
| 6 | `step5_c4_discharge` | 现有C/4放电 | 冻结`Q_ref`定义的目标容量 |
| 7 | `step6_udds` | 现有UDDS波形 | 现有容量窗口与事件保护 |

以下内容属于规范级不变量：

- 阶段顺序、数量和名称；
- 所有控制电流和控制电压；
- 所有电压、电流、时间和容量截止条件；
- RPT节点、预处理、恢复充电及静置；
- SOC定义、SOC边界和边界选择规则；
- 分阶段电量积分和库存核算方法；
- 温度、物理事件及结果有效性判定规则。

实现不得以“数值稳定”为理由隐式改变上述任一项。

## 5. 总体架构

### 5.1 新的标准充电执行边界

在后端增加单一职责的`StandardChargeSequence`执行边界。它一次接收
四个既有充电步骤，并使用同一个`pybamm.Experiment`和同一个
`pybamm.Simulation`连续求解：

```text
Protocol
  -> StandardChargeSequence
       -> 3c_cc
       -> 4v_cv
       -> c4_cc
       -> 4p2v_cv
  -> post_charge_rest
  -> step5_c4_discharge
  -> step6_udds
```

`post_charge_rest`、Step 5、Step 6和RPT继续使用现有协议控制路径。本次
不将整个老化循环合并成单一Experiment，以避免扩大到UDDS事件保护和
事务提交架构。

### 5.2 连续求解

标准充电Experiment包含一个由四个原生PyBaMM步骤组成的cycle。四步必须
用元组显式分组，防止PyBaMM把列表中的每一步解释为独立cycle：

```python
pybamm.Experiment([
    (
        pybamm.step.current(-14.55, termination="4.0 V"),
        pybamm.step.voltage(4.0, termination="0.05 A"),
        pybamm.step.current(-1.2125, termination="4.2 V"),
        pybamm.step.voltage(4.2, termination="0.05 A"),
    )
])
```

实际值必须来自`RunConfig`，上例仅表达协议映射。不得在此列表中加入
静置、斜坡、固定时长CV或其他隐藏步骤。

使用一次Simulation使PyBaMM在同一Experiment内部处理控制切换、模型
映射和一致初值计算，避免应用层对每个阶段重复重建Simulation。

### 5.3 结果接口

连续求解完成后，从本次新执行的cycle取得四个阶段解，转换为现有协议层
需要的阶段结果。由于`starting_solution`可能带有cycle偏移，实现必须在
求解前记录`cycle_offset`，求解后选择索引为`cycle_offset`的新cycle，或在
验证总数后等价地选择`solution.cycles[-1]`；禁止硬编码
`solution.cycles[0]`。转换结果必须保留：

- 原阶段名；
- 阶段起止时间；
- 原始终止原因；
- 规范化终止类别；
- 终端电压、温度、放电容量和状态哈希；
- 阶段墙钟耗时；
- 充电效率分析所需的逐阶段轨迹。

协议层仍观察到四个独立阶段，不感知后端由四次Simulation改成一次
Simulation。

## 6. 阶段边界与数据积分

每个相邻阶段允许共享同一物理时刻。输出可同时保留：

- 前一阶段终点样本；
- 后一阶段起点样本。

共享时刻代表控制条件切换，不代表额外经过的时间。所有电量和库存增量
必须继续按阶段局部时间网格积分，禁止将四段简单拼接后跨控制切换点做
梯形积分。

SOC边界插值、首次向上穿越选择、边界残差容限及重复边界样本处理继续
使用现有算法。架构调整不得改变这些规则。

## 7. 状态原子性

### 7.1 充电前快照

每次标准充电开始前创建不可变`pre_charge_snapshot`，至少包含：

- PyBaMM终端状态；
- 主模拟时间；
- 放电容量；
- 状态哈希；
- 当前循环；
- 当前结果事务编号。

### 7.2 临时求解

每次求解尝试必须在候选后端或等价隔离状态中完成。只有当完整四段充电
全部通过成功判定时，才允许将候选终端状态原子提交给主后端。

失败尝试不得：

- 改变主后端状态；
- 写入正式阶段轨迹；
- 向任何正式CSV追加记录；
- 增加已完成循环或事务编号；
- 覆盖最近有效检查点。

## 8. 求解器策略

### 8.1 首次尝试

首次尝试使用当前正式精度配置：

```text
rtol = 1e-5
atol = 1e-7
dt_max = 1.0 s
max_num_steps = 200000
max_error_test_failures = 10
max_order_bdf = 5
suppress_algebraic_error = false
dt_init = 0（IDA自动选择）
```

### 8.2 可重试错误白名单

只有底层错误码能够明确归类为以下错误时才允许重试一次：

- `IDA_ERR_FAIL`
- `IDA_CONV_FAIL`
- `IDA_LSETUP_FAIL`

错误识别应优先使用结构化异常类型或错误码；如果当前PyBaMM未暴露结构化
错误码，可在单一适配函数中解析`SolverError`消息。禁止在多个调用点散布
字符串匹配。

以下情况不得重试：

- 物理事件提前触发；
- 初始状态违反模型事件；
- 状态或输出包含NaN/Inf；
- 输出、检查点或文件系统错误；
- 配置、输入、环境或检查点指纹不一致；
- 用户中断或进程终止；
- 未识别异常。

### 8.3 保守重试

重试前必须丢弃首次候选解，恢复`pre_charge_snapshot`，并验证恢复状态哈希
完全一致。保守配置为：

```text
rtol = 1e-5
atol = 1e-7
dt_init = 1e-8 s
dt_max = 1.0 s
max_num_steps = 200000
max_error_test_failures = 30
max_order_bdf = 3
suppress_algebraic_error = true
```

`suppress_algebraic_error=true`仅在保守重试中使用。它从IDA局部截断误差
测试中排除恒压控制产生的代数电流变量，但仍要求每一步满足代数残差和
4.0/4.2 V约束；因此不改变控制目标、终止条件或物理状态方程。该选项由
cycle 9隔离探测确认是第10圈通过四段充电所必需的数值设置。

保守重试仍计算完整四段充电，不从失败的中间阶段继续。最多允许一次
重试。保守配置不允许通过放宽误差容限换取成功。

### 8.4 重试成功语义

重试成功时，循环业务状态仍为正常完成，但必须记录：

```text
solver_attempt_count = 2
solver_retry_used = true
initial_failure_code = <白名单错误码>
solver_profile = conservative_cv_transition
```

重试是数值执行细节，不改变物理协议或结果有效性规则。

## 9. 成功与失败判定

标准充电仅在同时满足以下条件时成功：

1. 恰好产生四个阶段解；
2. 阶段顺序严格为`3c_cc`、`4v_cv`、`c4_cc`、`4p2v_cv`；
3. 每段均由该阶段的预期事件终止；
4. 全局时间不倒退；
5. 阶段边界状态连续；
6. 终端标量和状态向量均为有限值；
7. 能够生成终端状态哈希；
8. 逐阶段轨迹通过现有结构和变量检查；
9. 充电分析通过现有SOC、电量及库存完整性检查。

任一条件失败时，整个标准充电事务失败，不允许提交前三段或其他部分结果。

## 10. 进度与心跳

连续Experiment必须通过PyBaMM step回调保留逐阶段进度。步骤索引固定
映射为：

```text
0 -> 3c_cc
1 -> 4v_cv
2 -> c4_cc
3 -> 4p2v_cv
```

进入每一步时立即原子更新`run_progress.json`。心跳线程继续按现有60秒
间隔更新。进度结构增加以下监控字段：

```json
{
  "solver_attempt": 2,
  "solver_profile": "conservative_cv_transition"
}
```

这些字段不进入检查点已提交静态工件清单，也不参与已提交前缀损坏判定。

首次失败后开始重试时，阶段可以从`3c_cc`重新显示；`solver_attempt=2`
用于区分这是完整回滚后的第二次尝试。

## 11. 输出兼容性与审计

以下现有正式输出的文件名、列名和语义不得改变：

- `cycle_summary.csv`
- `degradation_summary.csv`
- `charge_efficiency_summary.csv`
- `charge_efficiency_soc_bins.csv`
- `charge_timeseries/cycle-NNN.csv`
- `udds_cycle_validation.jsonl`
- RPT汇总和时序文件

必须新增`solver_attempts.jsonl`作为纯审计输出。每个完成或最终失败的标准
充电事务写一条记录，至少包含：

- 循环和事务编号；
- 尝试次数；
- 每次求解器配置标识；
- 初始失败错误码；
- 最终业务状态；
- 充电前后状态哈希；
- 四段终止原因；
- 每段模拟耗时和墙钟耗时。

审计记录不得作为科学指标参与SOH、效率或机理分析。

## 12. 失败取证与恢复

最终失败上下文必须增加：

```text
charge_stage
failed_step_index
solver_attempt
solver_profile
sundials_error_code
pre_charge_state_hash
last_successful_stage
last_committed_checkpoint
resume_checkpoint
resume_eligible
```

必须同时保留首次失败和保守重试失败的异常链。应用层通用
`RuntimeError`不得覆盖底层`SolverError`的错误码和消息。

`resume_eligible=true`只表示最近完整循环检查点已经通过指纹和输出清单
校验，可以作为新的正式恢复入口；它不表示失败尝试的部分解可以恢复。

若重试仍失败，程序继续写入`NUMERICAL_FAILURE`终态并安全退出，但不得
破坏最近完整循环的检查点和已提交输出。

## 13. 版本和检查点兼容性

物理协议版本保持不变。新增独立的`solver_execution_version`，并将其纳入：

- 运行配置审计；
- 检查点指纹；
- 环境/算法审计；
- 求解尝试记录。

旧版cycle 9检查点可以在隔离诊断中复现问题，但不得直接接入新版正式
结果目录继续生成cycle 10及以后结果。新版正式验证必须从cycle 0开始，
避免在同一结果集中混合两种数值执行算法。

## 14. 测试规范

### 14.1 单元测试

必须覆盖：

- 四个PyBaMM步骤与四个协议阶段的固定映射；
- 阶段缺失、重复或乱序时失败；
- 首次成功时不触发重试；
- 白名单错误触发一次完整回滚和重试；
- 非白名单错误不重试；
- 第二次失败后不再重试；
- 重试前后状态哈希一致性校验；
- 失败候选轨迹不进入正式输出；
- 阶段共享时间点不重复积分；
- 心跳正确报告阶段、尝试次数和求解配置；
- 最终失败正确引用最近有效检查点；
- 首次和第二次异常均进入失败取证。

### 14.2 真实PyBaMM集成验证

第一层为第10圈隔离复现：旧版cycle 9检查点只用于证明原失败可重复，
并验证新连续充电执行能够从同一物理状态完成第10圈标准充电。该结果不
进入正式结果集。

第二层为cycle 0至25回归：使用新版代码从cycle 0开始运行，完成cycle 25
及其RPT，且满足：

- 无数值失败；
- 所有阶段按预期事件终止；
- 无NaN/Inf；
- 温度、孔隙率、浓度和库存为有限值；
- 容量窗口误差符合现有阈值；
- 电量平衡状态不降级；
- 所有求解重试均有完整审计。

第三层为350圈正式验证：必须使用全新输出目录，从cycle 0开始。只有
完成全部循环、全部RPT节点、输出清单校验和SOH评估后，才能标记正式
成功。

### 14.3 新旧结果比较

对旧实现已成功的循环，采用以下回归容限：

| 指标 | 允许差异 |
|---|---:|
| 终端电压 | `<= 1e-6 V` |
| 终端温度 | `<= 1e-4 K` |
| 阶段充放电量 | `<= 1e-6 Ah` |
| 容量窗口相对误差 | 保持现有`<= 1e-3` |
| 电量平衡状态 | 不得降级 |
| 终止事件类别 | 必须完全相同 |

旧、新执行架构之间不要求状态哈希完全相同，因为求解路径变化可能产生
浮点级差异。同一新版代码、配置和环境的重复运行应保持确定性；若状态
哈希不能逐位一致，则所有正式科学指标必须在上述容限内一致，并记录
原因。

## 15. 实施范围

预计涉及以下模块职责。实现可以按现有命名风格选择函数名，但不得合并或
省略这些职责：

- `backend.py`：连续标准充电求解、候选状态和阶段结果转换；
- `protocol.py`：调用连续充电边界并保持现有分析接口；
- `model.py`：按求解配置构造首次与保守求解器；
- `types.py`：充电序列结果、求解尝试及失败上下文字段；
- `heartbeat.py`或对应进度模块：尝试次数和求解配置监控；
- `output.py`：求解尝试审计和失败恢复引用；
- `runner.py`：事务提交、最终失败状态和最近检查点关联；
- `tests/`：单元、事务、真实PyBaMM回归测试。

不得借本次实施重构无关RPT、UDDS、校准或SOH评估代码。

## 16. 完成定义

只有满足以下全部条件，修复才算完成：

1. 不可变实验协议逐项通过自动化断言；
2. 连续四段充电的阶段结果与现有输出接口兼容；
3. 重试严格从相同快照开始且最多一次；
4. 失败尝试不污染正式状态和输出；
5. 第10圈隔离复现验证通过；
6. 新版cycle 0至25回归通过；
7. 350圈全新正式验证通过；
8. 所有求解重试和最终失败均可审计；
9. 文档、配置指纹和检查点版本同步更新；
10. 未修改任何充放电控制量、终止条件、阶段顺序、模型参数或分析规则。
