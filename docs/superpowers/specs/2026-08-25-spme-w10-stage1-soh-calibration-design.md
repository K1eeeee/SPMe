# SPMe W10 第一阶段 SOH 老化参数标定设计规范

日期：2026-08-25  
状态：实施修订已获会话审批；等待书面修订审阅
范围：仅设计，不包含代码修改或长时间拟合执行

## 1. 背景

当前工程使用 PyBaMM SPMe、OKane2022 参数集、集总热模型，以及下列老化子模型：

- solvent-diffusion-limited SEI；
- partially reversible lithium plating；
- particle cracking；
- stress-driven loss of active material（LAM）。

cycle 0 容量已经完成标定：

- 固定容量倍率：`capacity_scale_factor = 0.95630859375`；
- 当前 SPMe cycle 0 容量约为 `4.868626135 Ah`；
- W10 实验 cycle 0 容量约为 `4.865884391 Ah`；
- 初始容量误差约为 `0.056%`。

因此，本阶段冻结容量倍率，只标定三个老化倍率。现有 `(1, 1, 1)` 基线对老化量的预测偏低：cycle 25、75、122 的 SOH 误差约为 `+0.46`、`+1.67`、`+2.82` 个百分点，且误差随循环增长。

最近一次 122 圈运行已完成，但部分充电恒压步骤发生首次求解失败，随后由统一重试配置恢复。正式标定开始前，cycle 23 附近的问题必须先完成修复和回归检查。

## 2. 目标与非目标

### 2.1 目标

本阶段的首要目标是提高 W10 长循环 SOH 预测精度，并交付：

- `sei_scale`、`plating_scale`、`lam_scale` 的最优组合；
- 一个按标定集预先确定的备用组合；
- cycle 0–188 标定结果；
- cycle 225–350 独立验证结果；
- 完整的参数、数据、检查点、失败、重试和排名审计记录；
- 最优候选的模型内部 SEI、析锂和 LAM 趋势。

### 2.2 非目标

本阶段不包括：

- 重新标定 cycle 0 容量；
- 使用 HPPC 或 EIS 构造目标函数；
- 增加欧姆内阻、交换电流、固相扩散或电解液传输参数；
- 进行大规模贝叶斯优化、全网格搜索或 MCMC；
- 将 SOH 拟合结果解释为实验上的唯一老化机理；
- 三组单机理消融或完整机理贡献分解。

HPPC/EIS 重排属于独立的第二阶段。

## 3. 数据划分与 SOH 定义

### 3.1 数据节点

cycle 0 只用于容量锚定和 SOH 归一化。

标定节点为：

```text
25, 75, 122, 146, 148, 151, 159, 188
```

独立验证节点为：

```text
225, 250, 275, 300, 325, 350
```

运行开始前必须将上述节点、实验容量、实验 SOH、数据来源和文件哈希固化成不可变目标清单。标定集和验证集不得交叉。

### 3.2 SOH 定义

实验和仿真分别相对于各自的 cycle 0 容量归一化：

```text
SOH_exp(c) = 100 * Q_exp(c) / Q_exp(0)
SOH_sim(c) = 100 * Q_sim(c) / Q_sim(0)
```

节点残差定义为：

```text
r(c) = SOH_sim(c) - SOH_exp(c)
```

误差单位统一为 SOH 百分点。绝对容量误差作为审计指标保存，但不进入本阶段老化参数目标函数。

### 3.3 数据隔离

cycle 225–350 的 SOH 在 cycle 188 排名完成前不得加载到候选生成器或排名器。最终验证结果不得用于调整参数、改变排名或生成新候选。

## 4. 参数空间

容量倍率固定为：

```text
capacity_scale_factor = 0.95630859375
```

三个老化倍率在对数空间表示：

```text
x_sei     = log10(sei_scale)
x_plating = log10(plating_scale)
x_lam     = log10(lam_scale)
```

统一边界为：

```text
-1 <= x_i <= 1
```

因此实际倍率范围为 `0.1–10`。

参数映射保持当前工程定义：

- `sei_scale` 作用于 `SEI solvent diffusivity [m2.s-1]`；
- `plating_scale` 作用于 `Lithium plating kinetic rate constant [m.s-1]`；
- `lam_scale` 同时作用于正极和负极 stress-driven LAM proportional constant。

不允许在同一阶段中临时改变某个候选的参数含义或边界。

## 5. 标定指标与排名规则

### 5.1 主指标

标定集普通 RMSE 为：

```text
RMSE_cal = sqrt(mean(r(c)^2))
```

其中 `c` 为八个标定节点。146–159 的四个密集节点保持独立计分，以保留该区间可能存在的老化加速或拐点信息。

验证集普通 RMSE 使用六个验证节点按同样方式计算。

### 5.2 分层排名

不将多个指标随意混合成单一加权分数。候选按以下顺序排名：

1. 候选必须数值有效，并完整到达本阶段要求的共同节点；
2. 优先选择标定 RMSE 更低者；
3. 标定 RMSE 相差不超过 `0.1` 个百分点时，选择最大单点绝对误差更小者；
4. 仍相近时，选择 cycle 188 绝对误差更小者；
5. 仍相近时，选择对数倍率偏离 `(0, 0, 0)` 更小者；
6. 最后选择统一求解策略下重试次数更少者。

所有临时比较只能使用相关候选共同到达的标定节点。最终排名要求候选到达 cycle 188。

## 6. 分层搜索流程

本阶段采用“单因素响应—组合候选—完整标定—一次验证”的固定流程，不运行通用全局优化器。

### 6.1 基线资格检查

基线候选为：

```text
(sei_scale, plating_scale, lam_scale) = (1, 1, 1)
```

正式运行前，基线必须完成 cycle 0–30 回归。只有模型物理选项、循环协议、有效参数、PyBaMM 版本和求解配置指纹一致，并且检查点续算等价性通过时，才能复用已有基线结果。

如果 cycle 23 修复改变了上述任一指纹，旧基线检查点失效，必须重新运行基线。历史结果仍可作为人工参考，但不得与新候选混合排名。

### 6.2 中倍率单因素探针

首先运行三个中倍率候选到 cycle 75：

```text
SEI-M:     (3.16, 1,    1)
PLATING-M: (1,    3.16, 1)
LAM-M:     (1,    1,    3.16)
```

cycle 25 只承担安全检查：

- 检查终止性求解失败；
- 检查非有限或明确非物理状态；
- 检查是否已经出现极端过老化。

cycle 25 不承担机理灵敏度筛选。

### 6.3 自适应高倍率探针

对每一种机理，在 cycle 75 计算中倍率相对基线的响应：

```text
delta_i(75) = SOH_i,mid(75) - SOH_baseline(75)
gap(75)     = SOH_exp(75) - SOH_baseline(75)
```

在以下任一条件成立时，补充对应的 `10` 倍候选并运行到 cycle 75：

- `delta_i(75)` 的方向不能减少当前基线误差；
- `abs(delta_i(75)) < max(0.05, 0.25 * abs(gap(75)))` 个百分点；
- 中倍率结果被标记为数值删失，无法估计响应；
- cycle 25 到75 的响应方向不一致，需要第二个幅值点判断非线性。

高倍率候选为：

```text
SEI-H:     (10, 1,  1)
PLATING-H: (1,  10, 1)
LAM-H:     (1,  1,  10)
```

因此单因素探针最少三组、最多六组。每种机理从有效的中/高倍率结果中选一个代表响应；优先选择能够减少 cycle 75 基线误差、不过度越过实验值且距离参数上界更远的候选。

### 6.4 局部响应近似

用基线和三个机理代表候选在 cycle 25、75 的 SOH 响应建立局部线性近似。对于代表候选的对数幅值 `x_i,rep`：

```text
SOH_hat(c, x) = SOH_baseline(c)
              + sum_i [x_i / x_i,rep * delta_i(c)]
```

该近似只用于提出组合候选，不作为最终验收依据。

### 6.5 组合候选 A

候选 A 是最小偏离解：

1. 在参数边界内最小化 cycle 25、75 的预测 SOH RMSE；
2. 将预测 RMSE 距最小值不超过 `0.05` 个百分点的解视为等效；
3. 在等效解中选择 `||x||_2` 最小者。

这使 A 优先满足 SOH，同时避免在欠定问题中无必要地把倍率推向边界。

### 6.6 组合候选 B

候选 B 用于保留机理组成上的多样性：

1. 计算 cycle 25、75 响应矩阵的最弱辨识方向；
2. 从 A 沿该方向的正负两侧生成可行解；
3. 要求 B 的预测 RMSE 不高于 A 超过 `0.1` 个百分点；
4. 在满足条件的解中，选择与 A 对数参数距离更大、且不优先贴近边界者。

如果不存在满足条件的不同组合，则 B 取预测排名第二且参数有效的解，并在报告中标记“未形成充分机理多样性”。

A、B 均必须从 cycle 0 独立运行到 cycle 122。不同倍率候选不得复制彼此的电化学状态。

### 6.7 标定至 cycle 188

A、B 都从各自 cycle 122 检查点继续到 cycle 188。任何在 cycle 122 前已经发生终止性数值失败或物理不可行的候选均不得继续。

到达 cycle 188 后，使用八个标定节点和第 5 节规则确定：

- 标定第一名；
- 标定第二名，即数值备用候选。

### 6.8 一次性验证至 cycle 350

仅将标定第一名从自己的 cycle 188 检查点续跑到 cycle 350，并一次性计算验证指标。验证结果不得反向调整参数。

如果第一名在验证区间发生终止性数值失败，可以运行预先由标定集确定的第二名。该动作只处理数值可执行性，不根据验证 SOH 选择更好结果。

如果第一名数值完成但预测精度未通过，不能改用第二名来挑选更好的验证误差；本阶段直接记录“外推验证未通过”。

## 7. 时间口径

用户给出的第一阶段计划目标为约 48 小时。依据当前约 `21.75 cycles/hour` 的实测速度，名义时间为：

- 三个中倍率探针至 cycle 75：约 10–11 小时；
- 最多三个高倍率补充探针：额外约 0–10 小时；
- A、B 从 cycle 0 至122：约 11–12 小时；
- A、B 从 cycle 122 至188：约6小时；
- 最终候选从 cycle 188 至350：约7–8小时。

不含额外高倍率探针时，名义总时间约 35–37 小时；全部高倍率探针均触发时，名义总时间约 45–47 小时。求解重试、重新生成基线或运行速度波动可能使总时间超过48小时。

时间组件只有监控职责：

- 记录累计墙钟时间；
- 根据近期循环速度估计当前阶段剩余时间；
- 估计完整流程剩余时间和预计完成时刻；
- 将估计值写入运行状态和最终报告。

它不得自动停止候选、跳过步骤、降低求解精度或改变搜索流程。48小时是计划目标，不是自动终止条件。

## 8. 系统组成与职责边界

第一阶段实现为独立的 SOH 老化标定工作流，现有 cycle 0 容量标定只提供只读输入。

### 8.1 目标数据读取器

读取 W10 容量数据，计算实验 SOH，固化标定/验证清单，并阻止节点缺失、重复或集合交叉。

### 8.2 候选生成器

生成中倍率探针、自适应高倍率探针和组合候选 A/B。它不运行 PyBaMM，也不访问验证数据。

### 8.3 候选运行器

应用倍率、执行循环、保存原子检查点并从同一候选的有效检查点续算。它不决定候选排名。

### 8.4 指标计算与排名器

计算节点残差、RMSE、最大误差和并列决胜指标。标定排名器只能访问 cycle 0–188 数据。

### 8.5 时间估算器

只观察和报告时间，不控制运行。

### 8.6 结果与审计记录器

保存配置、候选来源、运行状态、检查点、指标、失败、重试、排名和最终结论。

整体数据流为：

```text
实验容量数据
  -> 固定目标清单
  -> 中倍率单因素候选
  -> cycle 75 自适应高倍率判断
  -> 组合候选 A/B
  -> cycle 188 标定排名
  -> 第一名续算到 cycle 350
  -> 一次性独立验证
```

## 9. 运行状态、失败与重试

### 9.1 标准重试

每个循环步骤遵循统一流程：

1. 使用标准求解配置运行；
2. 已知数值求解失败时，从步骤开始前的有效检查点重新执行整个步骤；
3. 重试只使用预定义的统一重试配置；
4. 重试成功后提交结果并记录重试；
5. 不允许为单个候选临时放宽容差或无限增加重试。

失败尝试不得修改已提交的电池状态。只有完整成功的步骤才能生成新检查点。

### 9.2 状态分类

- `COMPLETED`：完整到达该阶段要求节点；
- `RETRY_SUCCESS`：首次失败但标准重试成功，结果有效；
- `NUMERICALLY_CENSORED`：标准重试后仍失败，候选未完成；
- `PHYSICALLY_INFEASIBLE`：参数或状态明确非物理；
- `DATA_INVALID`：目标数据缺失、重复或不可解析。

`NUMERICALLY_CENSORED` 不得被赋予人为的巨大 SOH 惩罚。它只是不具备参加完整排名的资格，不能被解释为物理性能差。

### 9.3 中途失败

候选中途失败时：

- 保留最后一个有效检查点；
- 保存完整错误分类、阶段、循环和求解器信息；
- 继续其他候选；
- 不从失败候选生成组合参数；
- 不修改其他候选的求解策略。

## 10. 检查点与可复现性

每个检查点必须绑定以下指纹：

- 候选三个倍率；
- 固定容量倍率和完整有效参数；
- 模型选项；
- 循环/RPT 协议；
- PyBaMM 与求解器版本；
- 标准和重试求解配置；
- 代码版本或工作区内容指纹；
- 已完成循环和诊断节点。

只有指纹完全一致才能续算。已成功完成的循环应幂等跳过；失败步骤从上一个有效检查点重新开始。

如果工作区没有 Git 元数据，必须使用配置文件和相关源文件的内容哈希代替提交号，以保证运行可追溯。

## 11. 验收标准

候选必须同时满足：

- cycle 0–188 标定 SOH RMSE `<= 1` 个百分点；
- cycle 225–350 验证 SOH RMSE `<= 3` 个百分点；
- cycle 350 SOH 绝对误差 `<= 4` 个百分点；
- 最终验证不存在终止性数值失败或物理失败。

如果标定未通过，不启动独立验证，并报告“标定精度未通过”。

如果标定通过但验证指标未通过，报告“外推验证未通过”，不得用验证集重新拟合。

如果验证因终止性数值失败未完成，报告“验证未完成——数值失败”，不得等同于 SOH 精度不合格。

## 12. 测试与运行前门禁

### 12.1 数据与配置测试

必须验证：

- 所有目标节点存在且唯一；
- SOH 归一化和 RMSE 计算正确；
- 参数边界和容量冻结值正确；
- 标定集与验证集无交叉；
- HPPC/EIS 未进入第一阶段目标函数。

任何失败都在启动 PyBaMM 长计算前终止。

### 12.2 工作流逻辑测试

必须覆盖：

- 对数倍率与实际倍率互换；
- 三个验收阈值的边界行为；
- cycle 25 只做安全检查；
- cycle 75 的高倍率触发规则；
- A/B 参数边界和生成可重复性；
- 分层排名和并列决胜；
- 时间估算器不控制运行；
- 数值删失不转化为 SOH 惩罚；
- 验证数据隔离；
- 不同候选不能复用彼此的状态。

### 12.3 数值回归测试

正式运行前必须：

1. 将基线运行到 cycle 30，确认 cycle 23 附近不存在终止性失败；
2. 比较连续运行与检查点续算结果；
3. 验证失败尝试不污染重试初态；
4. 验证标准重试成功后的容量和关键状态连续；
5. 验证修改参数或模型指纹后旧检查点被拒绝。

## 13. 输出与报告

每次正式标定生成独立输出目录，至少包含：

- 不可变目标清单；
- 模型、参数、协议、求解器和代码指纹；
- 所有候选及其生成依据；
- 周期级运行结果和检查点；
- 节点 SOH、残差和标定指标；
- 失败与重试事件；
- cycle 188 完整排名；
- 最终验证指标与通过/未通过结论；
- 运行时间和预计时间历史；
- SOH 对比曲线和节点残差图。

还应记录最优候选随循环变化的模型内部指标：

- total SEI loss、SEI thickness 或等价可用量；
- reversible plated lithium、dead lithium 和总析锂损失；
- negative-electrode LAM 和 positive-electrode LAM；
- 与上述量一致的 LLI、活性材料比例或电极容量指标。

这些指标只支持“模型内部趋势”描述。仅凭 SOH 优先标定，不得声称获得实验上的唯一机理贡献比例。

## 15. 2026-08-26 实施一致性修订

本节澄清并约束第一阶段实现；与前文存在歧义时，以本节为准。

### 15.1 cycle 25 安全门

cycle 25 不采用任意经验 SOH 下限。探针只因以下条件停止推进到 cycle 75：

- 终止性数值失败；
- 明确的物理不可行或物理协议失败；
- cycle 0 或 cycle 25 RPT 容量缺失、非有限或非正值。

记录 SOH 仅用于审计，不作为独立淘汰阈值。

### 15.2 组合候选与失败分类

- A 必须先求预测 RMSE 最优有界解，再在距其不超过 `0.05` 个百分点的可行解中选最小对数倍率二范数解；
- B 必须与 A 的对数倍率不同。优先使用最弱辨识方向上的、预测 RMSE 不高于 A `0.1` 个百分点的解；若不存在，则使用预先定义的有限候选集中的预测第二名，并记录降级原因；
- A 或 B 在 cycle 122 前发生数值删失或物理失败时，不得推进到 cycle 188；
- 仅标定第一名在验证区间发生 `NUMERICAL_FAILURE` 时，才可运行预先确定的第二名。物理协议失败直接报告验证失败，不得以 backup 替换。

### 15.3 运行上下文、检查点与目标隔离
